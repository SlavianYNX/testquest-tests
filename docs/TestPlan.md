# План тестирования: TestQuest — Калькулятор смет

## 1. Введение

### 1.1 Назначение документа
Данный документ описывает план тестирования веб-приложения **TestQuest — Калькулятор смет** (стенд: https://testquest.pryaniky.com/).

### 1.2 Объект тестирования
- **Приложение**: TestQuest — Калькулятор смет
- **URL**: https://testquest.pryaniky.com/
- **Раздел**: Продажи → Калькулятор смет
- **Продукт**: ПО «Бублики»

### 1.3 Цель тестирования
Проверить полный цикл работы калькулятора смет и интеграции с соседними разделами (Счета, Акты, Договоры).

## 2. Область тестирования (Scope)

### 2.1 Функциональность для тестирования
1. **Мета-данные КП**
   - Поля: Компания, Дата выставления КП, КП действительно до, Название проекта, Менеджер
2. **Тарифы**
   - TestQuest Облако (SAAS)
   - TestQuest Коробка (on-premise)
3. **Расчёт стоимости**
   - Количество пользователей (лицензий)
   - Срок лицензии (месяцы)
   - Применение скидок за срок
4. **Модули**
   - Базовая конфигурация (обязательные модули)
   - Ключевые модули (опциональные)
   - Дополнительные модули
   - Планируемые модули
5. **Услуги внедрения**
   - Проектирование
   - Разработка
   - Пилотная эксплуатация
   - Промышленная эксплуатация
6. **Time & Material**
   - Добавление часов
   - Расчёт по ставке
7. **Итоговая сумма**
   - Корректность расчёта ИТОГО
8. **Выгрузка в Excel**
   - Генерация файла .xlsx
   - Цветовая маркировка ячеек

### 2.2 Исключения (Out of Scope)
- Тестирование раздела «Договоры по форме клиента» (β-версия)
- Нагрузочное тестирование
- Тестирование безопасности
- Мобильная версия

## 3. Подходы к тестированию

### 3.1 Виды тестирования
- **Функциональное тестирование** — проверка соответствия требованиям
- **Интеграционное тестирование** — проверка взаимодействия с другими разделами
- **Регрессионное тестирование** — проверка существующей функциональности после изменений

### 3.2 Уровни тестирования
- **UI-тестирование** — через браузер с использованием Playwright
- **API-тестирование** — не применяется (клиентское приложение)

### 3.3 Автоматизация
- **Инструмент**: Python + pytest + Playwright
- **Покрытие**: ≥7 из 10 ключевых кейсов
- **Запуск**: через скрипты `run-tests.sh` / `run-tests.bat`

## 4. Критерии приёмки

### 4.1 Обязательные критерии
- ☑ Объект тестирования — именно Калькулятор смет TestQuest
- ☑ ≥10 тест-кейсов с полями: Название, Предусловие, Шаги, Ожидаемый результат
- ☑ Реализованы автотесты хотя бы по 7 из 10 кейсов
- ☑ Скрипты запуска работают «из коробки» на чистой системе
- ☑ Команда `BASE_URL=https://testquest.pryaniky.com ./run-tests.sh` выдаёт итог PASSED/FAILED
- ☑ README позволяет незнакомому человеку запустить тесты без консультаций

### 4.2 Критерии качества тест-кейсов
- Полнота описания шагов
- Однозначность ожидаемого результата
- Воспроизводимость
- Независимость (где возможно)

## 5. Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Недоступность стенда | Средняя | Высокое | Использовать локальную копию |
